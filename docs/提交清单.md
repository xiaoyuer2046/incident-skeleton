# 录屏脚本与 Devpost 提交清单（v4.1）

> 旧版脚本（v1）保存在 Git 历史中。本页以 v4.1 为准。

## 1. 录屏脚本（约 2 分钟；视频要短于 3 分钟）

提前准备：浏览器打开三个标签：`demo/guide-v4.html?lang=zh`、`demo/skeleton-v4.html?lang=zh`，以及在编辑器里打开 `skill/skeleton_v4/skeleton.py`。录屏分辨率 1920×1080，关掉通知。

| 时间 | 画面 | 旁白（可中可英） |
|---|---|---|
| 0–10 s | guide-v4 首屏 | 运维处理问题永远是六步：接收、初判、排查、处置、解决、记录。我们把这六步写成一个共用的运行时。 |
| 10–25 s | 编辑器里的 `skeleton.py` | 整个骨架只有 102 行。办公设备和服务台两个应用都调用同一个 `run()`，各自只写一个适配器。插件只能接在三个插槽上。 |
| 25–40 s | skeleton-v4 顶部“共用运行时”和两条泳道 | 应用 1 是机器报修，应用 2 是人报修。两个完全不同的应用，走的是同一条六步流程。 |
| 40–60 s | skeleton-v4“先学习”面板 | AI 先学厂商：微软 MCP、思科通告；再学公司内部；最后才看互联网。论坛内容要佐证，危险指令直接拦截，学习只能收紧权限。 |
| 60–85 s | skeleton-v4 的 Teams 事项和“一张微软总单”提示 | 很多人 Teams 登录不上，会议室 Teams Rooms 也进不了会。初判插槽发现是微软故障，两个应用挂到同一张微软总单，暂停重置密码和重装 Office。 |
| 85–100 s | skeleton-v4 的四楼无线事项 | 只有一层楼断网、思科正常，就按本地故障处理，优先用学到的修法，被思科通告标为有害的修法自动暂停。 |
| 100–115 s | `docs/agent-run-v4.md` 或 `.kiro/` 目录 | 用 Kiro 做：规格、steering、三个 hook、六个 agent 真实协作、自建 MCP、一个 Kiro power。 |
| 115–120 s | guide-v4 底部“如实现状” | 全部是演练和模拟数据，微软、思科和互联网的真实连接没有登录。 |

结尾字幕：`github.com/xiaoyuer2046/incident-skeleton` · Skeleton Crew。

录完上传到 YouTube（公开或不公开列出），把链接填到 Devpost。
