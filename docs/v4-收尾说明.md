# v4 收尾说明

v4 是 Kiroween 2026 · Skeleton Crew 的最终版本。v1、v2、v3、v3.1 的文件保持不变，作为历史。

## v4 解决了什么

1. **骨架真正共用。** 之前六步骨架只是名字相同，两个应用各自手写流程。现在只有一个运行时 `skill/skeleton_v4/skeleton.py`，两个应用都从它运行，各自只写适配器。
2. **仓库更清晰。** `VERSIONS.md` 列出当前文件和历史文件。评委只需要看一个入口页、一个演示页、一份 Devpost 文本。
3. **AI 先学习。** 学习不再只读公司内部资料，而是先读厂商 MCP 和官方状态，再读公司内部，最后读可信互联网和公众报告。

## 结构

- 六步：RECEIVE、TRIAGE、INVESTIGATE、MITIGATE、RESOLVE、LOG。顺序固定，插件和小组不能增删或改序。
- 三个插件插槽：`triage_gate`（全局故障判断）、`mitigate_rank`（方法排名）、`log_learn`（学习）。
- TRIAGE 内部顺序：安全拒绝 → 全局故障判断 → 已知故障关联 → 选择小组。
- 提前结束时，后面的步骤仍记录为"跳过"并写明原因，每条记录都有六步。
- 第三个应用只需新增适配器和配置，运行时文件不变。

## 学习规则

| 层级 | 来源 | 说明 |
|---|---|---|
| A | 厂商 MCP、官方状态 | 最先读取，权重最高 |
| B | 公司 KB、工单、聊天、邮件、共享文档 | 第二读取 |
| C | 可信互联网 | 需要 A 或 B 佐证 |
| D | 公众报告、论坛 | 需要佐证，且不能升降级任何方法 |

- 含指令、命令、凭据或权限请求的内容一律拦截并记录；未知动作和别的设备类型的动作也会被拒绝。
- 厂商公告说某方法有害时，该方法被暂停并通知相关人员。
- **学习只能收紧权限，不能放宽。** `policy.json`、`actions.json`、`app.json` 不会被写入，完整运行后保持逐字节一致。物理动作不会变成自动执行。
- 每次变化追加不可改的 `4.0.N` 版本，并生成一条双语 dry run 通知。来源没变就不生成。

## Teams 故障例子

Microsoft Teams 出现厂商故障时，服务台的两个登录请求和会议室的 Teams Rooms 故障都关联到**同一张微软总单**。密码重置和会议室 AV 修复被暂停，因为它们无法解决厂商侧问题。微软恢复且内部恢复后，关联单一起关闭并发出双语 dry run 通知。同一时间，思科健康时的单楼层 Wi-Fi 故障保持本地处理。

## 用到的 Kiro 能力

- `.kiro/specs/incident-skeleton-v4/`：需求、设计、任务。
- `.kiro/steering/incident-skeleton.md`：安全顺序与"只收紧"原则。
- 6 个 agent：`incident-crew-lead`、`printer-crew`、`signage-crew`、`av-crew`、`wifiap-crew`、`servicedesk-triage`。
- MCP：本地事件知识库服务。
- 定时任务：巡检和学习周期可作为定时任务运行。
- 跨平台 hook：`skill/hooks/audit_incident.py`（Python，Windows、macOS、Linux 通用），与旧的 shell hook 并存。

## 诚实说明

- 全部是 **dry run**，使用**模拟数据**。
- Microsoft、Cisco 和互联网的真实连接**均未登录**。
- 没有任何 dry run 结果代表外部系统发生了变化，也没有任何 dry run 修复被说成真实修复。
- 文档不写具体测试数量，请以最新一次测试运行的结果为准。
