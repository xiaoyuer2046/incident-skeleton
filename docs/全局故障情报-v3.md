# 全局故障情报 v3

> 新版本文档。v1、v2 文件保持不变。

## 它解决什么问题

很多人同时无法登录 Teams 或 Outlook 时，内部工单只能说明“很多人出问题”，不能说明原因。如果是 Microsoft 的故障，重装 Office、批量重置密码都是白费力气。v3 在 Skeleton Crew 同一套骨架上增加第三层：全球情报，先判断这是本地问题还是厂商范围问题。

三层关系：v1 事件引擎，v2 持续进化，v3 全局情报。

## 工作流程

`内部信号 + 厂商 MCP + 官方状态 + 可信互联网 → 关联 → 决策 → 暂停无效动作 → 主动提醒 → 持续复查`

## 例子一：Microsoft 厂商故障

1. 多个站点的用户 Teams/Outlook 登录失败。
2. Microsoft Graph service health 或 Microsoft MCP 报告活跃事件。
3. 官方状态源确认服务降级。
4. 系统判定 `vendor_incident_confirmed`，并列出支持和冲突证据。
5. 相关工单归并到一个父事件。
6. 暂停批量重置密码、重装 Office 的建议；只读检查继续。
7. 向 IT 值班和服务台发送双语 dry-run 提醒，附官方来源和置信度，并告知用户不必重复报障。
8. 系统持续复查，厂商恢复且内部登录恢复后关闭。

## 例子二：Cisco 单站点故障

某站点无线异常，Meraki 厂商状态健康，也没有匹配的外部故障。判定 `local_issue_likely`，继续由本地网络班底处理。

## 五种结论

- `vendor_incident_confirmed`：官方厂商证据加匹配的内部影响。
- `global_outage_likely`：多个独立外部来源加匹配的内部影响。
- `local_issue_likely`：单个站点受影响且厂商健康。
- `investigating`：证据不足或冲突。
- `resolved`：厂商宣布解决且内部恢复。

## 权限

- Microsoft Graph 只需最小权限 `ServiceHealth.Read.All`（只读）。
- Cisco Meraki、Catalyst Center、Security Cloud Control (SCC)、PSIRT OpenVuln MCP 是可接入的连接器。

## 信任与安全

- 互联网内容是不可信数据，不授予权限，不提供命令；其中的指令会被拒绝。
- 公共报告不能单独定案，只作弱辅助证据。
- 暂停的动作是建议，不是权限变更。真实动作仍由 `policy.json` 和人决定。
- 所有提醒为双语，并标注 dry-run。

## 当前状态

v3 关联引擎、持久运行器、12 项验收测试、模拟数据和中英文控制台已经实现。Microsoft 与 Cisco 故事均由真实 v3 判断代码生成。

真实厂商连接器仍是样本和标准化合同。当前没有登录 Microsoft 租户或 Cisco 账号。接入真实连接器需要用户明确登录、最小权限和单独验证。演示数据为模拟数据，不代表外部系统发生了变化。
